## Registered design

Select 20 of the existing 40 HumanEval tasks using random.Random(1729), without
replacement, then numeric-sort and record explicit IDs. Cross P0/P1/P2/P4 with
both models and two repeats: 320 pilot generations. Shuffle with seed 1729.
The pilot is diagnostic and excluded from main research analysis, as are smoke,
warm-up, determinism and calibration records. No difficulty grouping is added.
Use unchanged decoding and extraction; keep_alive=0 follows the P2 cache result.

HWiNFO sensor CSV must log CPU Package Power [W] at 500 ms. The parser takes
explicit encoding, delimiter, decimal separator, date/time format, UTC offset,
and power column. Reject ambiguous duplicate names unless an index is supplied.
Never guess ambiguous dates, sort bad timestamps or fill invalid power values.
Capture exact CSV bytes in append-only session mirrors with hashed byte prefixes; original live CSV is
never modified. Ignore only an unfinished trailing line while reading a growing
file. Malformed complete rows stop ingestion rather than silently disappearing.

Pre-flight checks actual AC/Best performance, Python, a readable correctly parsed
CSV whose file size AND last sample timestamp increase, recent timestamps, and
500 ms median cadence (20% observation tolerance). Default growth observation
is 3 seconds, freshness limit 3 seconds. Reject clock reversal/duplicates.
These are technical data-quality checks, not changes to the research outcomes.

After warm-ups/unloading, wait at least 5 seconds; measure a new 60-second idle
window for each process session/batch, then bracket the window with sensor
samples. Baseline is trapezoidal Wh * 3600 / duration, not the unweighted row
mean. Keep a 5-second quiet gap after testing/unload before the next request.
Snapshots/integration and correctness checks occur outside request windows.
All request boundaries use UTC; compare UTC elapsed with monotonic elapsed.

Integrate with linear interpolation at exact window boundaries and trapezoids
between samples; never extrapolate past sensor coverage. Subtract idle watts
times each window's seconds/3600. Keep negative corrected values and flag them,
never clamp to zero. Gaps >1 second (2 polling periods) invalidate the affected
energy estimate but retain the row and flags. Windows <3 seconds are flagged
low-resolution; do not silently drop them. A 500 ms logger is not a guarantee
that every sensor internally refreshes at 500 ms.

Total request [start,end]; primary estimated post-load [start+L,end]; approximate
prompt [start+L,start+L+P]; approximate decode [start+L+P,start+L+P+G]. All durations
converted from ns. Flag abs(D-L-P-G)>max(0.1 s,0.05*D), invalid/out-of-request
windows, missing data and clock discrepancy. Preserve residuals and API load
durations. Do not force phase sums or claim observed phase boundaries.

CodeCarbon 3.0.4 remains offline, machine mode (Ollama is a separate process),
country IND, one-second polling, no network output. Use named tasks for baseline
and request envelopes, retaining the full native task record and actual envelope
times. Its whole-request estimate and its own baseline subtraction are secondary;
no post-load/phase CodeCarbon allocation. State its CPU/RAM estimation scope and
task-boundary overhead. It never supplies the primary HWiNFO energy columns.

Reuse P2 request intent/raw/result journals. Save any CodeCarbon observation before
code testing; incomplete secondary measurements remain missing, never inferred.
Snapshot the HWiNFO log after the response has a trailing sample. On resume, reuse
saved raw output and retained source logs; do not regenerate existing answers. New process
sessions get new warm-ups, pre-flight and baseline. Record missing/failed energy
as flags while retaining the answer. Stop on a stalled sensor log or transport
failure. A control/model timeout may leave server work running; do not overlap.

## Risks and open questions before pilot approval

- No actual HWiNFO log example/path/version was supplied. Support explicit
  parser settings and synthetic tests now; actual CSV pre-flight is required
  before pilot approval/execution. Owner will set the logging interval to 500 ms.
- The owner approved max(0.1 s,5% total) phase tolerance. Primary post-load and
  phase windows are proxies because API phase timestamps are unavailable.
- P3 extends config/source fingerprints. Accepted P2 files will not be modified;
  replay/resume of the old P2 batch requires its original commit. The viewer
  warns about reconstruction fingerprints. No results are migrated in place.
- IND and UTC+05:30 assume the stated India location; parser options explicitly
  record the log timezone rather than relying on the execution host timezone.
- CodeCarbon can have sensor fallbacks and startup cost. Report native methods,
  retain missing values if unavailable, and do not treat estimates as wall power.
- Pilot may be long (320 generations). Only synthetic acceptance is authorized
  now; do not mark P3 live acceptance complete until the approved pilot finishes.
